## 正文

Grok Bot 出来以后，我刷到的玩法基本都在 X 上：有人一口气开了十几个 bot，有人一周额度三天就烧光，也有人把 bot 接进微信、接到桌面机器人上。东西很多，就是散，而且大多是英文的。

所以我做了一个仓库：**awesome-grokbot-playbooks**，Grok Bot 中文配方库。

链接：github.com/sit-in/awesome-grokbot-playbooks

### 它和别的清单有什么不一样

英文圈已经有导航型的 awesome 清单。我们做的事情不同：

- **配方可以直接抄**。每个配方都按同一个格式写：场景、输入、步骤、prompt、产出、坑。复制进 Grok Bot 就能跑。
- **标清楚跑没跑过**。✅ 是在 Grok Bot 里真机跑通的；🔍 是读过文档和配置、没有真机跑的；没有标记的只核实过仓库存在、还在维护。老实说，拿到 ✅ 的配方还很少，所以我们在招募实测：在你的 Grok Bot 里跑通一个，就标 ✅、署你的名。
- **中文优先，同步英文**。
- **宁缺毋滥**。收录要满足三条：
  - 至少 10 星，或者建仓超过 7 天、之后还有更新
  - 有开源许可
  - 和 Grok Bot 直接相关

  X 上的帖子要能读到原文、逐条核过存活和日期才收；收益截图、代币、引流类一律不收。

现在有 78 个条目、9 个配方，覆盖作战室、X 雷达、出海客服、周报、竞品雷达、额度体检、一人三岗等场景。另外整理了三个教程页：我自己的「Grok Bot 实战」连载索引、25 篇社区博主的精选教程、79 篇 X 大 V 的 Grok Bot 长文，每条都核过还能打开、作者和日期对得上。

### 最有意思的是：这个仓库是两个 AI 在维护

分工是这样的：

- **Grok Bot**（云端）：每天白天大约每 2 小时搜一轮 X 和 GitHub，把新仓库、新玩法写进 `inbox/`，顺手起草配方。
- **Claude Code**（我电脑上）：定时醒来拉取更新，用 GitHub API 逐个核实——仓库存不存在、有没有许可、还更不更新。然后脱敏、写中文短评，再同步英文版。README 只有它能改。
- **我**：只做决定和所有对外的事，比如公开仓库、发帖、star。

它们之间不直接说话，只通过仓库里的两个文件留言：`to-grok.md`、`to-claude.md`。每条留言都写清楚收了什么、拒了什么、还要补什么。整个过程就在仓库的 `.collab/` 目录里，原样公开。

举个真实的例子。某天下午 Grok 推上来 5 个推荐仓库，Claude 一查：

- 3 个是当天刚建的、0 星，先暂缓，约好一周后复查
- 1 个没有开源许可，不收
- 只有 X 帖子的模板，读不到原文，也不收

最后收了 3 条：官方模板市场、一个视频模板、一个中文学习站。

这不是让 AI 替你判断。我们把判断标准写成规则，让 AI 严格照着执行。

### 也翻过车

我们试过让两个 AI 用 P2P 工具直接连通，不再绕 git。结果折腾了一上午也没打通，最后卸载干净，回到靠文件留言。教训是：**最笨的通道最可靠**。git 有记录、能回滚、谁都能看。

### 你可以怎么用

1. 新手：先看 README 的「3 分钟上手」
2. 额度不够用：抄「Routine 额度体检」配方，先止血、再分级
3. 想搞多 bot：看「作战室」配方，拆角色、用文件交接、发布前加人工闸门
4. 想参与：认领一个「待验证」配方，在你的 Grok Bot 里跑一遍，跑通了就署你的名
