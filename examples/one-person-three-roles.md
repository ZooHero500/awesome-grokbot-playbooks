# 一人三岗：客服 + 内容 + 调研最小闭环

> 一个人做出海产品时，用三个分工明确的 bot 每天各跑一轮，人只做最后的判断和发布。

- **适合**：刚上线、还没人手的一人公司
- **验证日期**：待验证（本文为虚构示例草稿）
- **验证级别**：待验证
- **成本量级**：低

## 场景

一个人同时回用户消息、写内容、盯市场，每样都做不深。
把三件事拆给三个 bot，让它们每天定时产出草稿，人只花 30 分钟审核。

## 输入

- 客服：过去 24 小时的用户消息导出（邮件 / 表单 / 社群，先脱敏）
- 内容：产品更新日志、本周想讲的 1–2 个主题
- 调研：3–5 个竞品名称、2–3 个行业关键词

## 步骤

1. **调研 bot**（早上）：按关键词与竞品汇总最近 24 小时动态，输出 5 条要点
2. **客服 bot**（上午）：把用户消息归类为 bug / 需求 / 咨询，给每条咨询写回复草稿
3. **内容 bot**（下午）：读取前两步产出，写 1 条短帖 + 1 段更新说明草稿
4. **人工审核**（傍晚）：改、删、发。改动多的地方回写进 prompt

三个 bot 只通过文件交接（如 `out/research.md`、`out/support.md`），互不直接调用，方便单独调试。

## Prompt

调研 bot：

```text
你是 {{产品名}} 的市场调研员。
根据以下资料，列出最近 24 小时与 {{关键词}} 和竞品 {{竞品列表}} 相关的 5 条要点。
每条：一句结论 + 来源链接 + 对我们的影响（高/中/低）。
没有可靠来源的内容不要写。
```

客服 bot：

```text
你是 {{产品名}} 的客服助理。
把下面的用户消息分为 bug / 需求 / 咨询三类，输出表格。
对"咨询"类写回复草稿：语气友好、不承诺上线时间、不编造功能。
不确定的地方标 [需人工]。
```

内容 bot：

```text
你是 {{产品名}} 的内容编辑。
参考 research.md 和 support.md，写：
1. 一条 280 字以内的短帖，主题 {{本周主题}}
2. 一段 150 字以内的更新说明
不要使用夸张词，不要出现用户个人信息。
```

## 产出

```text
[research] 竞品 A 上线了批量导出；影响：中
[support]  bug 2 / 需求 3 / 咨询 5（其中 1 条标 [需人工]）
[content]  短帖草稿 1 条，更新说明 1 段
```

## 坑

- 客服消息必须先脱敏再喂给 bot，别把邮箱、订单号原样带进去
- 调研 bot 容易编来源，prompt 里要求"无来源不写"，审核时抽查链接
- 三步串行，前一步失败后面会空跑；每步先检查输入文件是否存在
