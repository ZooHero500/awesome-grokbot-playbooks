# X 雷达：每日抓取 + 摘要推送

> 用 Grok Bot routine 每天扫一轮 X/Twitter 公开帖，只把「有实质信号」的摘要推给你，噪音天不打扰。

- **适合**：一人公司 / 出海产品，需要盯关键词、竞品账号、行业话题，但没空整天刷时间线
- **验证日期**：2026-10-18（**待真机验证**；本文为脱敏虚构配方草稿，产品名与样例均为假）
- **验证级别**：待验证
- **成本量级**：低（取决于每日查询次数与推送渠道）

## 场景

手动刷 X 容易漏重点、也容易被噪声淹没。把「搜 → 筛 → 摘要 → 推送」收成一条 routine：有信号才推，无信号写「无更新」并结束。人只在傍晚花几分钟看摘要，决定要不要跟进或写内容。

## 输入

- 关键词清单：`{{关键词列表}}`（产品名、竞品名、品类词，3–8 个为宜）
- （可选）账号清单：`{{关注账号列表}}`（竞品官方 / 关键意见领袖，公开账号即可）
- 排除规则：广告话术、招聘、纯转发无评论等（写进 prompt）
- 推送目标类型：邮件 / IM / 笔记中的一种（只写渠道类型，不写真实地址）
- 上一次运行标记：`{{上次运行时间}}` 或当日已存在的雷达文件（避免重复推）

## 步骤

1. **定时触发**：建议每天 1 次（如上午）；别设成每小时，容易撞限流且摘要变碎
2. **检索**：按关键词 / 账号拉最近 24 小时公开帖；只保留可读原文 + 公开链接
3. **初筛**：去掉明显广告、无实质信息、重复转推；每类最多留几条代表
4. **摘要**：交给 bot 写成 ≤7 条要点；全部无实质信号则输出「无更新 · {{日期}}」并**跳过推送**
5. **落盘**：写入 `inbox/x-radar-{{日期}}.md`（或你约定的雷达目录）
6. **推送**：仅当有实质要点时，把摘要推到约定渠道；原文链接保留给人点开复核
7. **人工**：需要跟进的标进「需人工」清单；发布短帖 / 对外回复仍由人确认

## Prompt

```text
你是 {{产品名}} 的 X/Twitter 雷达。
根据以下公开检索结果（关键词 {{关键词列表}}，可选账号 {{关注账号列表}}），
汇总最近 24 小时有实质信号的要点，最多 7 条。

每条格式：
一句结论 | 类型(产品/定价/内容/舆情/其他) | 公开帖链接 | 置信度(高/中/低)

规则：
- 没有可点开的公开链接不要写
- 不要推测未出现在原文里的功能、数字或立场
- 广告、招聘、无评论纯转发、与关键词无关的帖子直接丢弃
- 若全部无实质信号，只输出一行：无更新 · {{日期}}
- 变量用 {{占位符}}；不要写入真实客户信息或内部路径

额外输出（仅当有要点时）：
- 「需人工」：值得跟进、需写回复、或不确定是否相关的 0–3 条
```

推送包装（给人看的频道消息，可再套一层）：

```text
X 雷达 · {{日期}} · {{产品名}}
{{要点列表或「无更新」}}
来源均为公开帖；未自动点赞/回复/发帖。
```

## 产出

虚构示例（产品与事件均为假）：

```text
# inbox/x-radar-2026-10-18.md
1. 话题 {{关键词}} 下出现可复核讨论，提到批量导出 | 内容 | https://example.com/x/status/1 | 中
2. 竞品账号 @NorthwindFake 发了更新预告长帖 | 产品 | https://example.com/x/status/2 | 高
需人工：是否把第 1 条转成内容选题

# 推送（有信号时）
X 雷达 · 2026-10-18 · AcmeTools
- ……（同上压缩版）
其余：已过滤广告与无评论转推
```

## 坑

- **假链接 / 编造帖**：模型会补「看起来合理」的 status URL；prompt 强制「无公开链接不写」，审核时抽查能否打开
- **噪声天照样推**：时间戳、推荐位、无意义改动会制造「有变化」幻觉；无实质信号必须输出「无更新」并跳过推送
- **把 routine 当成互动机器人**：雷达只读公开帖、只摘要；点赞、回复、发帖、关注一律人确认
- **关键词过宽**：品类大词会淹没信号；先收窄到 3–8 个，再按一周误报率加减
- **与竞品雷达重复**：官网/changelog 归 `competitor-radar`；X 只盯社媒话语与舆情，交叉时在摘要里标「已在竞品雷达出现」避免双推
- **时区混乱**：约定用团队常用时区写「最近 24 小时」与文件名日期，避免跨日漏扫或重扫
