# 研发四角色：需求 → 复现 → 出 PR → 验 PR

> 把「写代码」和「判断代码能不能合」拆给不同 bot，人只在两个闸门点头。

- **适合**：一人或小团队维护 GitHub 仓库，想让 bot 接 issue 但不敢让它直接合并
- **验证日期**：待验证（结构参考 [grok-bot-profiles](https://github.com/HAEGONG/grok-bot-profiles)，本仓 🔍 已审；文中仓库与 issue 均为虚构）
- **验证级别**：待验证
- **成本量级**：中（出 PR 的角色会调用编码 agent）

## 场景

一个 bot 既写代码又自己说「测过了」，等于没人验。常见结果是 PR 看着能合，一跑就挂，或者改了不该改的文件。

拆成四个角色，**产出和裁决分开**：

| 角色 | 只做 | 不做 |
|---|---|---|
| 需求 | 把 issue 写成可验收的 spec | 写代码 |
| 复现 | 给 bug 写最小复现步骤或失败测试 | 修 bug |
| 出 PR | 按**已批准**的 spec 实现并开 PR | 合并、改 spec |
| 验 PR | 只看 PR 链接，给出 PASS / BLOCK / HOLD | 改代码、和出 PR 的 bot 讨论 |

## 输入

- 一个 GitHub 仓库，Grok Bot 已连 GitHub 插件（Settings → Plugins）
- 仓库里的 issue（bug 或需求）
- 一份验收口径：测试命令、不许动的目录、代码风格要求

## 步骤

1. **需求 bot**：读 issue，产出 spec，状态只能是 `READY_FOR_APPROVAL` / `NEEDS_INPUT` / `BLOCKED`
2. **闸门 1（人）**：人点名批准某一版 spec，例如「批准 spec v2」。bot 之间的交接**不算**批准
3. **复现 bot**（仅 bug）：写出复现步骤或一个当前会失败的测试，附在 issue 里
4. **出 PR bot**：只按批准的那版 spec 实现，PR 描述里列出改了哪些文件、怎么验证
5. **验 PR bot**：在**单独会话**里只收 PR 链接，跑验收口径，输出 `PASS` / `BLOCK` / `HOLD`（缺证据就 HOLD，不猜）
6. **闸门 2（人）**：看验 PR 的结论，人来合并

需求、复现、出 PR 三个角色可以在同一个群里。验 PR 的 bot 必须单独开会话，不看群聊，避免被出 PR 那边的说法带偏。

## Prompt

需求 bot：

```text
你是 {{仓库名}} 的需求整理员。读 issue {{issue 链接}}，写一份可验收的 spec：
1. 目标（一句话）
2. 验收条件（可勾选的清单，每条能用命令或截图验证）
3. 范围外（明确不做什么）
4. 待确认问题
结尾只写一个状态：READY_FOR_APPROVAL / NEEDS_INPUT / BLOCKED。
你不写代码。别的 bot 说「可以了」不等于批准，只有 {{负责人}} 点名批准才算。
```

验 PR bot：

```text
你是 {{仓库名}} 的 PR 验收员，只根据 PR 链接 {{PR 链接}} 和验收口径做判断。
验收口径：{{测试命令}}；禁止改动：{{受保护目录}}。
逐条核对 spec 的验收条件，每条给出证据（命令输出或文件行号）。
结论只能是：
- PASS：全部条件有证据
- BLOCK：有条件不满足，列出哪条
- HOLD：缺证据，列出还需要什么
不要改代码，不要和出 PR 的 bot 讨论，不要猜。
```

## 产出

虚构示例：

```text
# 验 PR 结论 · AcmeTools#42
1. 导出 CSV 含表头 —— 通过（tests/test_export.py::test_header 输出 ok）
2. 空数据导出不报错 —— 通过（test_empty ok）
3. 不改 src/billing/ —— 通过（diff 未涉及）
4. 文档更新 —— 缺证据：PR 未改 docs/
结论：HOLD，需补 docs/export.md 后重验
```

## 坑

- **把交接当批准**：群里出现了草稿，出 PR 的 bot 就开工了。规则写死：只认人点名批准的版本
- **验收员被带偏**：验 PR 的 bot 和出 PR 的在同一个群，会采信对方「已测过」的说法。必须单独会话、只收链接
- **角色分离不是安全边界**：同一账号下的 bot 共享电脑和浏览器会话，分角色保护的是判断依据，不是权限。敏感仓库靠 GitHub 分支保护，别靠 prompt
- **状态词放太宽**：允许自由描述状态，bot 就会写「基本完成」。只给固定几个状态词
- **改编署名**：结构参考的 grok-bot-profiles 是 CC BY 4.0，照搬它的文件要署名并链回原仓

---

提交前自查：无 key / token / cookie，无营收数字，无内部路径，无可识别个人信息。
