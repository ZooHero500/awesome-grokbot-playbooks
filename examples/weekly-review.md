# 周报 routine：每周五自动出初稿

> bot 每周五把这一周散落的工作痕迹收成一份周报初稿，人花 10 分钟改完就发。

- **适合**：一人公司或小团队负责人，每周要给自己、合伙人或社群交代进展
- **验证日期**：待验证（本文为虚构示例草稿）
- **验证级别**：待验证
- **成本量级**：低

## 场景

周报难写，往往不是因为没做事，而是事情散在 GitHub、文档、聊天和日历里，周五凭记忆写，漏掉一半。

让 bot 每周五定时去几个固定地方收集痕迹，按固定结构出初稿。人只负责删减和补上「为什么」。

## 输入

- 数据源（按需选，只给只读权限）：
  - GitHub：本周合并的 PR、关闭的 issue
  - 文档：本周新建或改过的文档标题
  - 日历：本周的会议标题（不含参会人）
  - 待办：本周完成项和延期项
- 上周的周报（用来对照「上周说要做的，做了没」）
- 读者是谁：自己 / 合伙人 / 社群（决定写多细）

## 步骤

1. **建 routine**：每周五 {{时间}} 触发，只读上面几个数据源
2. **收集**：按数据源分别列出本周痕迹，每条附链接
3. **对照**：拿上周周报里的「下周计划」逐条标记：完成 / 部分完成 / 未做
4. **成稿**：按固定结构写初稿，存到 `out/weekly-{{日期}}.md`
5. **人审**：删掉不该对外的，补上取舍的原因，再发

## Prompt

```text
你是 {{名字}} 的周报助理。现在是 {{日期}}，请整理本周（周一到今天）的进展。
数据源：{{数据源列表}}；上周周报：{{上周周报路径}}。

按下面结构输出，每条事实附链接，没有链接的不写：
1. 本周完成（最多 5 条，按影响排序）
2. 上周计划对照：每条标 完成 / 部分 / 未做，未做的写一句原因（不知道原因就写「待补」）
3. 卡点（需要别人帮忙的）
4. 下周计划（最多 3 条）

规则：
- 不写营收、用户数、客户名等经营与隐私信息
- 不夸大，不写「大幅提升」这类没有数据支撑的词
- 读者是 {{读者}}，按这个读者决定写多细
```

## 产出

虚构示例：

```text
# 周报 · 2026-W42

## 本周完成
1. 导出功能上线 CSV 格式（AcmeTools#42）
2. 竞品雷达 routine 改为只推实质变化，噪音从每天 20 条降到 3 条
3. 新增 2 个配方草稿

## 上周计划对照
- 上线导出功能 —— 完成
- 写 3 篇配方 —— 部分（2/3，第 3 篇待补）
- 约 2 位用户访谈 —— 未做，待补

## 卡点
- 需要一位懂 iOS 的朋友看下推送问题

## 下周计划
1. 补第 3 篇配方
2. 完成 2 位用户访谈
```

## 坑

- **数据源权限给太大**：只需要读，别给写权限，更别给邮箱发信权限
- **无链接的「成果」**：bot 会根据聊天记录脑补完成项。prompt 要求每条附链接，审稿时抽查
- **原因瞎编**：「未做」的原因 bot 不知道时会编一个。要求它写「待补」，由人填
- **隐私外泄**：日历和聊天里有人名、客户名，对外发之前人工过一遍
- **routine 空跑**：假期那周没有痕迹，bot 仍会凑一份。加一条：本周少于 2 条痕迹就只写一句「本周无实质进展」

---

提交前自查：无 key / token / cookie，无营收数字，无内部路径，无可识别个人信息。
