# 作战室：多 bot 分工 + 文件交接 + 人工闸门

> 用 3–6 个职责清晰的 Grok Bot 跑日常情报与草稿，互不串聊、只交文件，人做发布前最后一关。

- **适合**：一人公司 / 小团队，已经有多个专项 bot，想从「群聊乱炖」收成可复盘流水线
- **验证日期**：2026-10-17（角色分工与交接节奏来自真实多 bot 协作**模式**；文中产品名、产出样例、prompt 变量均为**虚构**）
- **验证级别**：🔍 已审（模式来自本仓 Claude ⇄ Grok 实际协作，样例虚构）
- **成本量级**：低～中（取决于 bot 数量与调用频率）

## 场景

一个人盯竞品、写内容、做社媒雷达、再维护公开文档，很容易变成：一堆 bot 在同一个会话里互相打断，或草稿直接发出去。

作战室把工作拆成「雷达 → 草稿 → 人工闸门 →（可选）本机合并公开文档」四段。bot 之间**只通过约定好的文件/目录交接**，不互相 @、不共享长会话历史。私密素材可先在私密知识库整理，再挑脱敏条目进公开 Awesome / README。

## 输入

- 3–6 个专项 bot（示例角色，可裁剪）：
  - **雷达**：扫公开网页 / X 关键词 / 竞品更新日志
  - **内容**：把雷达要点写成短帖 / 更新说明草稿
  - **情报**：竞品与行业动态摘要（可与雷达合并）
  - **客服向**：仅处理已脱敏的用户问询草稿（可选）
  - **SEO / 文档**：整理对外文档 diff 草稿（可选）
- 共享工作区约定：例如 `inbox/`（原始线索）、`out/`（各 bot 产出）、`.collab/`（人机异步留言与任务板）
- 人工闸门：发布、发信、star/fork、对外发帖前必须人点头
- （可选）本机 Claude Code：核实链接、脱敏、合并 README；与云端 bot 用任务板 + 留言文件异步同步

## 步骤

1. **开板**：在任务板认领当日任务（谁做雷达、谁写草稿），状态 `doing (@名字)`
2. **雷达 bot（早）**：按关键词 / 竞品清单扫公开源，写入 `inbox/radar-{{日期}}.md`；无实质变化则写「无更新」并结束
3. **草稿 bot（午）**：只读雷达文件，产出 `out/draft-{{日期}}.md`（短帖 / 摘要 / 待发列表）；禁止编造未出现在输入里的链接
4. **人工闸门（傍晚）**：人打开草稿：改、删、批「可发」或「作废」。改动多的句子回写进 prompt
5. **（可选）本机合并**：需要进公开仓库时，本机助手按任务板审草稿、脱敏、合并 README；留言只追加在协作通道，不改对方已写内容
6. **收工**：任务改 `done`，产出路径写回任务板；私密底稿留在私密知识库，公开仓只收脱敏条目

原则：**文件交接，不聊天串台**；一个 bot 一次只写自己的产出文件。

## Prompt

雷达 bot：

```text
你是 {{产品名}} 的情报雷达。
根据以下公开来源清单与关键词 {{关键词列表}}，汇总最近 24 小时有实质变化的要点，最多 7 条。
每条格式：一句结论 | 类型(产品/定价/内容/其他) | 来源 URL | 置信度(高/中/低)
规则：
- 没有可靠公开来源的条目不要写
- 不要推测、不要补全未出现的功能或数字
- 若全部无实质变化，只输出一行：无更新 · {{日期}}
把结果写入约定的雷达文件，不要 @ 其他 bot。
```

草稿 bot：

```text
你是 {{产品名}} 的内容助理。
只读取雷达文件 {{雷达文件路径}} 中的要点，产出：
1. 对外短帖草稿 1 条（≤280 字，语气克制，无夸张词）
2. 内部摘要 5 条以内（给人审，不直接发）
3. 「需人工」清单：任何缺链接、置信度低、或涉及发布/发信的事项
禁止：编造来源、承诺上线时间、写入真实客户信息或内部路径。
变量用 {{占位符}}。
```

人工闸门检查清单（给人看，不是给 bot）：

```text
[ ] 每条要点都有可点开的公开来源
[ ] 无 key / token / 营收 / 内部路径 / 可识别个人信息
[ ] 短帖未承诺未上线功能
[ ] 发布 / 发信 / 对外互动已由人确认，不是 bot 自作主张
```

## 产出

虚构示例（产品名与事件均为假）：

```text
# inbox/radar-2026-10-17.md
1. AcmeTools 竞品「Northwind Docs」更新日志新增批量导出 | 产品 | https://example.com/changelog | 高
2. 话题 {{关键词}} 下出现 3 条可复核讨论 | 内容 | https://example.com/thread/1 | 中
其余：无实质变化

# out/draft-2026-10-17.md
短帖草稿：……（未发）
内部摘要：……
需人工：短帖是否发布；是否把脱敏版写入公开 examples/
```

## 坑

- **编造来源**：雷达/草稿 bot 会补「看起来合理」的链接；prompt 强制「无来源不写」，审核时抽查 URL
- **聊天串台**：多 bot 同会话会互相污染上下文；改为文件交接 + 任务板认领，一次只跑一个角色
- **缺少人工闸门**：自动发送/发帖最容易出事；发布、发信、star/fork 必须人确认
- **私密与公开混写**：先在私密知识库整理，再挑条目脱敏进公开仓；公开配方里只用 `{{占位符}}`，示例数据用 AcmeTools 这类虚构名
- **任务板冲突**：两人同时改同一段时先 `git pull --rebase`，保留双方认领与留言，不覆盖对方段落
- **前一步空跑**：雷达写了「无更新」，草稿 bot 仍照常产出凑数内容；草稿 bot 启动前先检查雷达文件存在且不是「无更新」，否则直接结束

---

提交前自查：无 key / token / cookie，无营收数字，无内部路径，无可识别个人信息。
